# 使用说明

## 源码运行（Python 3.13+）

1. 使用 [Jujutsu](https://docs.jj-vcs.dev/latest/) 克隆项目（Git 后端，兼容 GitHub）：

```bash
jj git clone https://github.com/Samueli924/chaoxing chaoxing
cd chaoxing
```

2. 安装依赖：

```bash
python -m pip install .
```

安装后可使用 `chaoxing` 命令；开发时使用 `python -m pip install -e .`。

3. 直接运行：

```bash
python main.py
```

4. 配置文件运行：复制 `config_template.ini` 为 `config.ini`，修改账号密码等配置。

```bash
python main.py -c config.ini
```

5. 命令行运行：

```bash
python main.py -u 手机号 -p 密码 -l 课程ID1,课程ID2 -a retry
```

课程列表和关闭章节策略可省略。也可使用模块入口 `python -m chaoxing_app` 或安装命令 `chaoxing`，参数相同。

若系统 Python 版本不符合要求，可使用 `uv` 选择解释器：

```bash
uv run --python 3.13 main.py
uv run --python 3.13 main.py -c config.ini
```

## 打包文件运行

1. 从上游 [Releases](https://github.com/Samueli924/chaoxing/releases) 下载可执行文件。
2. 直接运行：双击运行。
3. 配置文件运行：下载 `config_template.ini` 保存为 `config.ini`，修改配置后执行 `./chaoxing.exe -c config.ini`。
4. 命令行运行：`./chaoxing.exe -u "手机号" -p "密码" -l "课程ID1,课程ID2" -a retry`。

## Docker 运行

构建镜像：

```bash
docker build -t chaoxing .
```

运行：

```bash
# 使用镜像中的默认配置模板
docker run -it chaoxing

# 挂载自己的配置
docker run -it -v /本地路径/config.ini:/config/config.ini chaoxing
```

Docker 默认读取 `/config/config.ini`。模板由 `Dockerfile` 在构建镜像时复制到该位置，不是首次启动时自动生成；运行真实账号前应编辑配置并挂载。

## 题库配置

在配置文件的 `[tiku]` 中填写 `provider`（大小写一致）及 token 等必要信息，使用 `-c 配置文件路径` 启动。

题库也可从默认 `config.ini` 读取配置：复制模板后只填写题库部分，不传 `-c` 时题库仍可按默认文件初始化。对含章节检测且后续任务需要解锁的课程，题库与提交设置影响能否继续。

题库名对应 `api/answer.py` 的 registry，例如 `TikuYanxi`。多个 provider 按逗号列出的顺序回退；具体字段以 `config_template.ini` 为准。

### 保存与提交

无题库配置时跳过需要答题的任务。覆盖率指题库搜到的题目占全部题目的比例。

- `submit=true`：达到覆盖率时提交，未达到时保存；不能保证答案正确。
- `submit=false`：只保存搜到的答案，随后可自行检查、修改与提交。不正确的 `submit` 值按 false 处理。

手动模式及已经进入重做流程时还有专门提交判定；修改此行为前阅读架构边界与相关代码，不把普通覆盖率说明当作全部策略。

### 重做

`[common]` 的 `work_redo_enabled=false` 默认不自动重做，适用于只允许一次作答的课程；`work_max_retries` 控制开启重做后的最大重做次数。开启可能再次提交作答，使用前确认课程允许。

## 未开放章节策略

`[common]` 的 `notopen_action` 或命令行 `-a`/`--notopen-action` 控制策略：

- `retry`：重试同一未开放章节，调度器默认累计五次尝试后停止该章节；不会自动回滚到上一章节。
- `continue`：跳过未开放章节，不重试。
- `ask`：参数仍可接受，但实现没有询问分支，与 `retry` 走同一处理逻辑；不要依赖它弹出询问。

```bash
python main.py -a continue
```

重试间隔由 `retry_interval` 控制，CLI 的 `--retry-interval 0` 保留零值。上述描述以 `chaoxing_app/jobs.py` 的实现为准；工作流迁移没有修复 `ask` 功能。

## 章节学习次数

`[common]`：

- `add_learning_count=false`：是否在课程任务后增加章节学习次数。
- `target_count=100`：章节学习次数目标总次数。

开启后先完成所选课程的任务点，再执行学习次数增加；这是追加步骤，不是独立运行模式，也会产生远端副作用。

## 外部通知

外部通知在课程流程结束或出错时发送。配置 `[notification]` 的 `provider` 和必要 `url`，Telegram 还需要对应字段；未配置时禁用通知。具体服务与示例见 `config_template.ini`。

## 验证范围

离线回归不覆盖真实登录、题库请求、直播、作答提交或学习次数上报。账号、Cookie、API key、token 与本地日志不得入库。开发入口及验证命令见 [开发说明](开发说明.md)。
