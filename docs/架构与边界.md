# 架构与边界

## 模块职责

| 路径 | 职责 |
| --- | --- |
| `chaoxing_app/config.py` | 参数解析与 INI 类型转换，不加载网络依赖 |
| `chaoxing_app/cli.py` | 登录、课程选择、通知与任务执行编排 |
| `chaoxing_app/jobs.py` | 章节任务、队列、有界重试与线程生命周期 |
| `api/` | 平台协议、题库、通知、验证码与页面/字体解码 |
| `resource/` | 随包分发的字体映射数据 |
| `tests/` | 无网络回归测试 |
| `main.py` | 源码及 PyInstaller 薄入口 |
| `app.py` | 独立 Flask/Celery 集成，不属于 CLI 执行路径 |

三种 CLI 入口为源码脚本、模块运行和安装命令，使用相同编排。运行版本和包内容以 `pyproject.toml` 为准。

## API 模块导航

- `api/__init__.py`：格式化响应字典辅助函数。
- `api/base.py`：`Chaoxing` 客户端、会话、登录与学习功能。
- `api/answer/`：题库包，`core.py`（查询核心与实例状态）、`cache.py`（JSON 缓存）、`fallback.py`（回退链）、`registry.py`（provider 注册表与构造入口）、`providers/`（各题库实现与手动输入）。
- `api/answer_check.py`：答案校验、切分、归一化与作答详情判分。
- `api/cipher.py`：登录使用的 AES 加密。
- `api/config.py`：协议常量与文件路径约定。
- `api/cookies.py`：Cookie 文件读写。
- `api/decode.py`：课程、章节、任务卡片、题目页面与作答记录解析。
- `api/cxsecret_font.py`、`api/font_decoder.py`：字体映射与解码。
- `api/exceptions.py`：领域异常。
- `api/logger.py`：日志与手动输入期间的输出协调。
- `api/interaction.py`：唯一手动输入锁及状态查询，手动 provider、日志与视频展示共同依赖，不反向加载题库。
- `api/notification.py`：通知工厂及服务实现。
- `api/process.py`：进度展示及学习次数追加流程。
- `api/captcha.py`：验证码获取、识别与验证，OCR 依赖缺失或初始化失败时不可用。
- `api/live.py`、`api/live_process.py`：直播请求与执行流程。

API 拆分按 [.agents 内的施工方案](../.agents/api重构施工方案.md) 分阶段实施：阶段 2（纯函数与小模块）、阶段 3（数据解析）与阶段 4（题库拆包）及第四节缺陷修复已完成。本轮已补充离线请求对照，并完成阶段 5 的交互解耦部分；整个阶段 5 尚未完成，会话管理拆分和阶段 6 尚不实施。

## 字体资源

`resource/font_map_table.json` 保存字形名称与哈希的映射；解码时根据字形哈希寻找原始字符。数据由包声明分发，源码环境和 PyInstaller 使用不同资源基准目录，不依赖调用方工作目录。

## 行为契约与改动门槛

以下是改动前需要明确差异的边界，不代表每项实现已无缺陷：

- 请求签名、加密、表单字段、时间单位、请求顺序和验证码恢复都是平台协议的一部分。重构先保持发送内容，再单独处理行为修复。
- `StudyResult.SUCCESS` 表示该路径按既有约定结束；保存成功、成绩未知等情形也可能返回它，不能据此断言服务端已确认任务点完成。
- 章节执行先处理全部任务点再汇总失败；任务队列必须在完成或异常时关闭并回收线程。
- provider 回退顺序、答案索引、手动校验豁免、缓存与反馈作用域影响答题结果；改动需要消费者可见的回归场景。
- 传输重试、题页重试、记录轮询、验证码恢复、测验重做与章节重试是不同机制，不能为简化代码合并为统一扩大重试。
- CLI 编排与 API 请求/解码职责分离；跨层移动需同时迁移所有引用和打包配置，不留无用兼容路径。

### 缺陷修复契约（本轮定案）

以下契约在本轮缺陷修复中生效，详细差异与验证方式见 [施工方案第四节修复契约](../.agents/api重构施工方案.md)：

- 题库查询：单题 `query()` 与批量 `query_all()` 对同一输入必须同结果；缓存未命中时返回经校验的 provider 答案并回写缓存；存在错误反馈时按既有规则跳过缓存。
- 缓存并发：指向同一缓存文件的实例共享同一把进程内锁，读-改-写不再丢更新；只有"文件不存在 / JSON 或编码损坏 / 根节点不是 JSON 对象"才按空缓存继续，其他读取异常按"缓存不可用"处理（读视为未命中、写跳过），不得吞成空缓存后覆盖整表。跨进程并发不在范围。
- 会话生命周期：进程内只构造一次 Session 并加锁，cookie 变更通过显式同步接口生效；不再每次获取都新建会话。
- 测验重做计数：属于单次测验调用的局部状态，不跨任务留存，避免改变后续测验的保存/提交判定。
- 直播失败：执行流程的失败返回值必须向外传播并交给既有章节重试；每分钟上报失败的一次重试只记录日志，不改变控制流，避免重复上报时长。
- 未开放章节：`ask` 仍与 `retry` 同分支（未实现询问），启动时记录一条 warning 说明；实现真正询问属行为变更，需另行授权。
- 无题库实例：与题库停用一样跳过该任务点，不再因访问顺序抛异常。

以上边界变化先更新本文或新增明确决策文档，再实施相应代码与验证；新增决策同时更新文档索引。

### 本轮离线对照与交互解耦契约

- `tests/fixtures/api_contracts/` 仅保存合成输入和当前实现的离线请求预期；固定时间、替身 Session 截获视频签名/上报与测验保存/提交/重做表单，不读取真实凭据或发送网络请求。现有解析、缓存、provider 顺序与任务状态回归继续复用；真实响应留档仍为验证缺口。
- 手动输入的唯一非重入互斥锁迁入轻量的 `api/interaction.py`。手动 provider、日志 sink 和视频进度展示统一查询它，不再从日志反向访问题库模块。
- 保持日志缓冲上限 1000、顺序及解锁后下一条日志触发冲刷的时机；保持视频进度条锁定时关闭、解锁后恢复，以及输入异常时锁释放的现有语义。日志初始化仍在导入时执行，`process.py` 不拆分。
- 仅改变内部依赖，不改变请求、播放计时、重试、`StudyResult`、Session 生命周期或线程模型；不引入线程本地 Session、全局请求锁或新的协议策略。


## 验证与外部副作用

离线测试覆盖局部规则、解析、配置与调度，不证明账号登录、题库服务、验证码、直播或作答提交的真实协议可用。

只读远端验收与提交/上报验收分开。真实账号、Cookie、API key、token 和响应中的身份信息不入库。会提交作答、签到、观看进度或增加学习次数的 smoke 需要授权与可控测试课程，禁止用真实作业试刀。

HTTP 库、加密库、缓存存储格式与全局状态策略未在本次文档迁移中改变。相关缺陷的复现与风险分别记录在 agent 施工方案和踩坑文档中。
