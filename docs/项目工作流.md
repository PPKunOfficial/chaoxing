# 项目工作流

## 来源与适用范围

本项目按 `personal_workflow` 的项目配置入口裁剪工作流，而非复制整套模板。通用规则的唯一真源是该仓库的 `global/AGENTS.md`；项目特有约束放在根目录 [AGENTS.md](../AGENTS.md)。

本机真源为 `/Users/pp/projects/personal_workflow`。其他环境通过自己的 `personal_workflow` 路径读取并分发全局规则；本项目不包含指向某台机器的符号链接，不修改工具全局配置，也不维护一份通用规则副本。

## 四层入口

| 路径 | 内容 |
| --- | --- |
| `AGENTS.md` | 项目专属约束与规则，不写现状或任务进度 |
| `README.md` | 项目定位与导航 |
| `docs/` | 面向人的使用说明、架构、决策与操作细则 |
| `.agents/` | 面向 agent 的踩坑、待办、跨会话记忆与施工方案 |

用户文档从 [文档索引](README.md) 进入；agent 续作从 [.agents 导航](../.agents/README.md) 进入。文档搬迁不保留双份正文，旧模块 README 只保留导航。

## 开工与变更

1. 阅读项目规则、受影响文档和 `.agents/` 中相关记录，区分已经实施的行为、拟议方案和待确认风险。
2. 使用 `jj status` 判断已有改动归属。用户原有改动不自动纳入本次提交；不重复初始化仓库。
3. 多文件或跨模块任务先确定文件边界、行为差异和可观察的验收方式。等价重构与修复分别列项，线上副作用场景先确认授权。
4. 在独立 Jujutsu change 内实施一件事，同步调用方、测试、文档与打包路径；临时产物放仓库外。
5. 运行对应离线验证与实际入口 smoke，记录观察到的结果及未覆盖场景。已知故障先定位，不重复运行同一检查只为确认用户报告。
6. 验证后按 [Jujutsu 工作流](jj工作流.md) 使用中文 gitmoji 约定式提交收尾。提交不等于推送；不自行移动已发布的书签。

## 环境与验证入口

运行时约束见 `pyproject.toml`，运行依赖来自 `requirements.txt`，测试使用标准库 `unittest`。仓库未配置统一 lint 或类型检查命令，不将未运行的工具写成通过。

开发入口和构建命令见 [开发说明](开发说明.md)。使用 `uv` 可选择项目要求的解释器并安装依赖：

```bash
uv run --python 3.13 python -m unittest discover -s tests -v
uv run --python 3.13 chaoxing --help
uv build
```

行为变化还需对应流程 smoke；完整测试、帮助命令或构建通过，都不能代替真实远端协议验证。远端验收限制见 [架构与边界](架构与边界.md)。

## 工作流文档自检

使用真源校验器，不在项目内复制一份会漂移的脚本。默认路径示例：

```bash
sh "$HOME/projects/personal_workflow/scripts/check-agents.sh" AGENTS.md README.md api/README.md resource/README.md .agents/README.md docs/README.md
```

若真源在其他位置，替换脚本路径。校验器只检查规则与导航是否混入现状，不能证明链接有效或架构正确；还需检查本地链接和分发文档。

## 依赖与决策门槛

默认复用现有 Python 标准库、HTTP 库、题库 registry 和通知工厂；没有明确需求时不引入新核心依赖、不更换加密或网络技术栈。变更这些边界前在架构文档中说明风险、迁移调用方与验证方式。

没有另行设立 RFC 或强制 PR 评审流程；需要用户决定的新依赖、协议策略或线上操作，在对应任务中集中提出，而非虚构审批制度。待定事项与可验证验收方式记入 `.agents/todos.md`。

## 本次文档迁移的纠偏

- 旧 README 描述未开放章节重试上一个章节三次，并称 `ask` 会询问。`chaoxing_app/jobs.py` 实际重试同一章节，默认上限五次；只有 `continue` 单独跳过，`ask` 与 `retry` 同分支。使用说明按实现标注，不改变代码。
- Docker 模板由 `Dockerfile` 在构建时复制到 `/config/config.ini`，不是首次启动时自动生成。
- `api/README.md` 曾将验证码模块标为未启用，视频流程已有验证码调用；架构文档改为说明可选 OCR 与恢复流程。
